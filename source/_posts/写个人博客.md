当我重新整理个人知识库时，发现博客依旧是最稳妥的载体：可控、可搜索、可沉淀，也足够自由。于是决定重新梳理一次写个人博客的流程，把想法和实践都记下来。

<!--more-->

## 为什么要写
- 把零碎的聊天和备忘录变成可复用的文章，方便未来的自己查阅。  
- 公开输出逼着自己把问题讲清楚，减少“一知半解”的错觉。  
- 留下一条明确的成长轨迹，也许几年后回看会很有趣。

## 技术选型
我依然使用 **Hexo + GitHub Pages**。理由简单：静态站点足够快，维护成本极低，托管也免费。命令行流程很顺畅：

```bash
hexo new "写个人博客"   # 创建新文章
hexo s                 # 本地预览
hexo g -d              # 生成并部署
```

主题方面继续沿用当前样式，少折腾，先把内容写出来。

## 写作工作流
1. **选题和大纲**：先在草稿里写出 3-5 个要点，再展开成段落。  
2. **首屏摘要**：用 `<!--more-->` 控制首页摘要，让读者能快速判断是否感兴趣。  
3. **示例与链接**：用最小可运行的命令或代码片段，给出出处或延伸阅读。  
4. **复盘**：发布后第二天再读一遍，修掉措辞或补充遗漏。

## 内容方向
- 真实踩坑：系统定制、嵌入式小工具、自动化脚本。  
- 工具心得：编辑器配置、调试技巧、效率习惯。  
- 生活记录：读书、电影、旅行和随机想法。

## 运营与维护
- **备份**：Git 仓库就是备份；公共发布与源码分开存放，防止被主题更新意外覆盖。  
- **素材管理**：开启 `post_asset_folder`，图片与文章同目录，迁移不易丢。  
- **监控**：偶尔跑一次 `npm audit` 看依赖安全性，定期 `hexo g` 验证站点是否能正常构建。

## 写在最后
写博客不是赶进度，而是把当下想法放到能公开检视的地方。期待未来能在这里留下更多的实验与故事。***
